# UNIT-7.2 — Server: authorize the board doc by user id; drop the boards table and `/boards`

Part of plan `docs/plans/2026-07-12-002-refactor-collapse-board-linear-columns-plan.md` (Unit 2). Satisfies R2, R3, R7.

## What changed

The `board:{userId}` sync room is now authorized purely by **identity** — the parsed doc id must equal the authenticated user's id — with **no `boards` ownership-table lookup**. Board registration is gone entirely: the `boards` table, the `/boards` routes, and the DB reads that consulted it are removed. This mirrors the identity check the `workspace:` branch already used.

- **`apps/server/src/sync/authz.ts`**
  - Dropped the `boards` import and the `drizzle-orm` `eq` import.
  - The `board:` branch now authorizes iff `ref.boardId === consumed.userId` (identity), replacing the `boards.ownerId` DB lookup. The `workspace:` branch is unchanged (it already did this). `parseDocumentName` still parses both `board:<id>` and `workspace:<id>`.
  - `SyncAuthDeps.db` is retained (callers still pass it; other call sites of the deps shape are unchanged) but is no longer read by `authenticateConnection`.
- **`apps/server/src/sync/naming.ts`** — **kept** `workspaceDocName` (still used by `routes/commands.ts`, so not unused); `boardDocName` unchanged (`board:{id}`).
- **`apps/server/src/routes/boards.ts`** + **`apps/server/src/routes/boards.test.ts`** — **deleted** (`POST /boards`, `GET /boards`, `POST /boards/:id/archive`).
- **`apps/server/src/app.ts`** — removed the `boardRoutes` import and its registration block.
- **`apps/server/src/db/schema.ts`** — removed the `boards` `pgTable` (and its `boolean` import, now unused) and its entry in the `schema` object.
- **`apps/server/drizzle/0001_careful_stick.sql`** — **new migration**: `DROP TABLE "boards" CASCADE;` (plus the `drizzle/meta/_journal.json` entry and `0001_snapshot.json`), generated by `drizzle-kit generate`. Not applied to any DB — committed only.
- **`apps/server/src/routes/ticket.ts`** — the `POST /sync/ticket` board branch now uses the same identity check (`ref.boardId === userId`); dropped the `boards`/`eq` imports and the now-unused `db` binding.
- **`apps/server/src/routes/commands.ts`** — the board-scoped authorization now checks `boardId === userId` (identity) instead of a `boards` lookup; dropped the `boards`/`eq` imports and the now-unused `db` binding. (The command surface itself — `boardId` on inputs, `getWorkspaceDoc` — is untouched here; that is Unit 4.)
- **Tests** — `sync/hocuspocus.test.ts`, `routes/ticket.test.ts`, `routes/commands.test.ts`, `db/schema.test.ts` reworked to the no-table identity model (details below).

## Why

- **Authorize by identity (R2):** boards are 1:1 with users, so an ownership table is redundant. The room id *is* the owner's id — `ref.boardId === userId` is the whole check. This is the same shape the `workspace:` room already used and closes the durability bug where a client-chosen id (`"main"`) never registered and its room denied sync.
- **Remove the board entity (R3):** with no per-board ownership to record, `POST /boards`/registration and the `boards` table are pure dead weight. `ticket.ts`/`commands.ts` consulted the same table, so their board branches collapse to the identity check too (they live in the server app, so fixing them here is in scope; the ticket route in particular *must* match the sync authz or no ticket would ever issue).
- **Reset, not migrate (R7):** the `boards` rows are abandoned; the migration drops the table. No data is carried forward.

## How it works

`authenticateConnection` runs the same ordered gate as before — origin allow-list → consume the one-time ticket → ticket's `documentName` must equal the requested doc — then, instead of a DB read, it compares the parsed id to `consumed.userId`. For `board:<id>` and `workspace:<id>` alike, the id must be the caller's own; anything else throws `SyncUnauthorizedError` before any sync. Because the origin check still runs first, a disallowed origin fails without consuming the ticket (behavior preserved). `POST /sync/ticket` performs the identical identity check before issuing, so the ticket and the sync handshake agree.

Scenarios covered (in `sync/hocuspocus.test.ts`, DB-gated):
- **Happy:** a ticket for `board:{userId}` issued to that same user authorizes and returns `{ userId }`.
- **Error:** a valid ticket for `board:{otherUserId}` (room id ≠ caller) is rejected with `SyncUnauthorizedError` before any sync.
- **Error:** a mismatched `documentName` (ticket minted for a different doc) is rejected.
- **Error:** a disallowed origin is rejected first and the ticket survives (never burned).
- **Workspace parity:** a user's own `workspace:{userId}` authorizes, another's does not.
- `routes/ticket.test.ts` — `POST /sync/ticket` issues for the caller's own `board:{userId}` and workspace, and 403s for another user's board/workspace.
- `db/schema.test.ts` — asserts the migrated schema contains `users`/`refresh_tokens`/`yjs_documents`/`link_metadata_cache` and **does not** contain `boards`.

Edge / "no table access remains": `grep -rn "\bboards\b" src/sync/authz.ts src/routes/ticket.ts src/routes/commands.ts src/db/schema.ts src/app.ts` returns nothing; the `boards` symbol and `routes/boards` are gone from production code.
